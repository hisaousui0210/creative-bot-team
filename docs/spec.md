# 要求と受入条件

状態: 実装着手前 / 今回は準備のみ。

## 目的と初期利用者

会話と直接操作を組み合わせ、個人の制作判断を次の編集へ引き継ぐWeb制作環境を作る。初期利用者は本人1名で、ローカル環境内の複数プロジェクトを扱う。アプリ実装とモデルの実接続は別の工程として進める。

最初の完成単位M0は、AI接続を使わずに作品を直接編集・保存できる画面。M1は「トップの印象が重いから、もっと軽快にして」という人工シナリオを、根拠・参謀レビュー・判断・変更・記憶まで追えるmockの一往復。M2で確認済みの実接続へ置き換える。

## 非目標

M0/M1では任意のHTML/JavaScriptの実行、汎用ソースコード編集、ネイティブアプリ生成、多人数共同編集、一般公開、SNS投稿、課金、無人の定期実行、モデル追加学習を含めない。作中のボタンは編集・表示対象で、外部送信を行わない。

M1のmockは入力を固定したシナリオ用。任意の日本語要求を理解できるとは表示しない。Devin固有の接続が未設定でもM0/M1を進められる構成にする。実際のBotや子セッションが稼働した証拠はM2で記録する。

## 入出力と状態

直接操作はSceneMutationを送信し、更新後のSceneとrevisionを受け取る。自然言語要求は保存済みmessageIdからジョブを作り、状態と結果を取得する。Sceneの詳細はarchitecture.md、メモリのJSON形式はpackages/contracts/contracts.schema.jsonを正本にする。

ジョブはqueued/running/succeeded/failed/awaiting_user/cancelled。候補はcandidate/active/rejected/conflicted/expired、有効メモリはactive/superseded/revoked/expired。取消要求は別のcancelRequestedフラグで管理し、遅れて届く結果を適用しない。

400は形式・サイズ、409はrevisionまたは冪等キー競合、422は根拠・昇格条件違反、503は接続先の停止。実接続の失敗をmockの成功で黙って置換しない。

## 記憶と権限

今回の本人の明示指示を過去の推定より優先する。今回だけの指示はsessionに限定する。user全体への昇格には、その範囲を示す本人の明示が必要。推定には異なる本人発言の根拠が2件以上必要で、同一messageIdの再処理を数えない。

imported資料は現在の本人の承認にしない。fixtureの発言はprovenance=liveを含む場合も、シナリオ全体のdataOrigin=syntheticによって実データと隔離する。実際の本人のメモリへfixtureを昇格させない。

デモはテストプレイが終わるまでローカル。起動時のモデル接続はmockを既定とし、実接続、追加課金、公開範囲を自動変更しない。認証情報・私信・SQLite実データはGitへ入れない。

## 受入条件

| ID | 対応 | 合格条件 |
|---|---|---|
| AC-001 | R-001,002 | 人工ページで要素追加→移動→属性変更→Undo→Redo→再読込を通し、期待したSceneへ戻る |
| AC-002 | R-003 | 古いrevisionを409で拒否。同一キー・同一本文は同じ結果、同一キー・別本文は409 |
| AC-003 | R-004,008 | fixtureの要求からvisual.densityをsession範囲で抽出し、恒久的な白背景・動きの嫌悪を推測しない |
| AC-004 | R-005,007 | 2役のレビュー、修正、最終判断、Sceneの差分を同じjobIdで追える。議論は最大2ラウンド |
| AC-005 | R-004,006 | 引用不一致、Bot発言、importedだけの根拠、推定の根拠重複を昇格できない |
| AC-006 | R-006 | 訂正・撤回後に旧メモリがeffective viewから外れ、他project/sessionへ漏れない |
| AC-007 | R-007,009 | 再起動時に中断ジョブをfailedとして表示し、明示的な再開でも適用済みactionを二重反映しない |
| AC-008 | R-008,009 | 実装後の日本語READMEどおりDocker起動でき、mock・人工データの表示と再起動後の保存を確認する |

M0の完了範囲はAC-001、AC-002、AC-008の直接編集部分。M1で残りを追加する。現時点は上記の実装・受入確認は未実施。
