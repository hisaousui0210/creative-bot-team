# 構成と状態管理

制作環境はWeb画面、API、SQLite、役割別の実行処理、モデル接続Adapterから構成する計画。

最初はCreative ProducerをDevin Botとして設定し、Extractor、参謀A/B、Builder、QAを作業別の子セッションとして起動する。役割の指示はprompts配下を正本にする。Devin Botの接続が子に引き継がれる条件を確認し、厳密な権限分離が必要ならBotと接続を分ける。

Devinの記憶には開発上の要約と参照先を置き、制作上の記憶の正本はアプリ側のSQLiteで管理する。候補の根拠、適用範囲、採否、訂正・失効を追跡する。

候補はcandidateからactive/rejected/conflicted/expiredへ、有効な記憶はsuperseded/revoked/expiredへ遷移する。記憶を昇格する前に、原文、話者、出所、対象の範囲、競合、レビューをサーバーで検証する。

APIの更新はrevisionと冪等キーを使い、記憶の昇格・旧版失効・判断記録をトランザクションで扱う。専用ツールはこれから実装するものなので、現段階では利用できると仮定しない。

通常の画面操作はSceneデータへの構造化操作として扱う。コードを変える必要がある開発作業は、別のBuilderジョブで差分を作る。作品データの編集とアプリのソースコード変更を同じ処理とみなさない。

クラウドの子セッションと本人のローカルPCは別環境。共通のSQLiteを各VMから直接開かず、確認済みのAPI経路を使う。経路未設定時は人工データとJSON成果物で検証する。
